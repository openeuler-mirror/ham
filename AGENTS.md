# AGENTS.md

## Project Overview

HAM (High-Availability Migration) - A high-availability live migration service that leverages the Lingqu bus's remote memory access capability and high bandwidth to achieve deterministic-duration VM live migration, solving planned-downtime problems and enabling system high availability. C/C11 CMake project targeting openEuler Linux (ARM64), delivering the `libham.so` shared library.

## Build Commands

```shell
# Release build
./build.sh -t release

# Debug build
./build.sh -t debug

# Debug build with UT (DEBUG_UT, for DT only)
./build.sh -t debug --ut

# Clean build directory and output
./build.sh -t clean

# Default build (no type, defaults to Release)
./build.sh
```

## Test Commands

```shell
# Initialize the remaining third-party submodule (first time)
git submodule update --init --recursive

# Build and run all DT tests with coverage report
./test/run_dt.sh

# Run specific test case via gtest filter (after building ham_dt)
cd test/build && ./ham_dt --gtest_filter="TestSuiteName.TestCaseName"

# Coverage report is auto-generated by run_dt.sh via lcov/genhtml
# into test/build/gcovr_report/
```

## Code Style

- C++11 / C11 standard (C++17 when compiler >= 7.3)
- clang-format for formatting (via pre-commit hooks)
- clang-tidy for static analysis (Release build for src, Debug build for test)
- Comments in Chinese or English as appropriate

## Dev Environment Tips

- Requires GNU C++ compiler >= 7.3
- Default build type follows `cmake/building.cmake` (empty type -> Release)
- Tests use googletest (downloaded from src-openeuler at build time) and mockcpp (submodule under `test/3rdparty/`)
- `test/run_dt.sh` initializes submodules and patches mockcpp for ARM64 automatically
- `compile_commands.json` is in the build directory (`build/`, `test/build/`)
- Build output lands in `output/ham/` (`lib/libham.so`, `include/ham.h`)
- Release build packages a tarball: `ham_1.0.0_<os>-<arch>_<type>.tar.gz`
- libboundscheck (Huawei secure C) is expected at `/usr/lib64/libboundscheck.so`
- Security build flags enabled: stack-protector-strong, PIE/PIC, relro, now, noexecstack

## Security Guidelines

**禁止行为（安全红线）：**

1. **禁止提交密钥信息**
   - API 密钥、密码、Token、认证私钥
   - 数据库连接字符串、财务凭证
   - SSH 私钥、GPG 密钥

2. **禁止硬编码凭证**
   - 用户名/密码
   - Access Key/Secret Key
   - 认证 Token

3. **禁止绕过安全机制**
   - 禁用 SSL/TLS 验证
   - 注入或删除安全相关代码
   - 关闭认证/授权机制

4. **禁止记录安全日志**
   - 记录敏感数据（密码、Token、个人信息等）
   - 明文记录凭证

**其他要求：**

- 使用环境变量或独立配置文件存放凭证，并将其加入 `.gitignore`
- 不要提交含有真实数据的测试数据
- 定期轮换可能泄露的密钥与凭证
- 发现安全漏洞请负责任地报告

## Commit Guidelines

- Run `./build.sh -t release` before committing (enforced by pre-commit hook `run-build`)
- Test file changes are checked by pre-commit hook `run-build-test`
- Ensure clang-format and clang-tidy checks pass (pre-commit hooks)
- Add or update tests for code changes
